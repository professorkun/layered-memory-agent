# 架构与设计原理

> 本文是博客文稿 `docs/blog-post.md` 的技术底稿：同样的设计，去掉叙事、补上实现细节与参数出处。

## 1. 要解决的问题

最常见的聊天机器人记忆是「按天数硬切」：近 3 天留原文、4~30 天压成要点、
31 天以上一句话、最多 20 条。它只有一个变量——时间。于是「随口一句吃面」
和「一句很重的话」在同一天被一起压扁。这不是遗忘，是定期删档。

但只换一条更聪明的衰减曲线也不够。真正缺的是**分层**：
哪些东西压根不该衰减、哪些东西该从事件里长出来、哪些东西只是查到的而不是记得的、
哪一层允许谁写。本系统把这些拆开，每层只负责一件事。

## 2. 三套正交的分层维度

| 维度 | 层 | 生命周期 | 谁写 | 衰减 |
| --- | --- | --- | --- | --- |
| 按职责 | 上下文 / 我的记忆 / 知识库 | 上下文不落盘；记忆长期；知识库独立 | 人 / 引擎 / 人 | 无关 |
| 按保鲜度（浅→深） | L1 近 3 天原文 / L2 4~30 天要点 / L3 更早一句话 | 按时间窗逐级压缩 | 蒸馏器 / 日记任务 | 按分量（事件层） |
| 按抽象程度（浅→深） | 事件 → 感觉 → 沉淀 → 底感 / 深层模式 | 越深越慢、越不该被每轮改写 | 引擎出候选，**人审后**才写 | 极慢 / 不衰减 / 改系数 |

**最容易接错的地方**：两套编号都叫 L1/L2/L3，但含义完全不同。
本实现一律用语义名（`Layer.EPISODIC`、`Layer.GROWTH_BASE` …），
`LayeredView.time_layers()` 里才保留 L1/L2/L3 这套旧名，并明确注明「编号不通用」。

### 2.1 按职责：上下文 ≠ 记忆 ≠ 知识库

- **上下文**：本轮这几句，说完就过去。冲突时「刚发生的事以上下文为准，事实类以记忆为准」。
- **我的记忆**：我怎么经历、怎么感觉、怎么想。分 `chat/`（事件）、`facts/`（稳定字段）、
  `self/`（生长）、`conscious/`（状态连续体）。
- **知识库**：确认过的事实，谁都能查。**库里写着 ≠ 我记得**；查到的事说完就过，不往记忆里搬。

### 2.2 按保鲜度：给多少原文

`LayeredView.time_layers()`：L1 ≤3 天给原文，L2 4~30 天按周取前 5 条并截断到 60 字，
L3 ≥31 天每天一句话、最多 20 条。预算 4000 字时按
「单条截断 → 每轮留最新几行 → 只留最近 12 轮」逐级压缩（`compress()`）。

这一层只管**读多少**，不管**还剩多少**；后者是事件层衰减的职责。两者正交，别混。

### 2.3 按抽象程度：事件怎么长出深层

| 层 | 文件 | 权限 | 关键约束 |
| --- | --- | --- | --- |
| L0 底感 | `self/layers.json:base_feel` | 手写，人点头 | 无来源、无日期、不衰减，5~9 条，半年复核 |
| L1 感觉 | `self/layers.json:feel` | 引擎出候选，人审写 | 从 residue 沉下来；记忆掉了它还在 |
| L2 事件 | `live/` → `daily/` → `index/` | 蒸馏器 / 日记任务 | 六变量衰减，原始证据只读 |
| L3 沉淀 | `self/layers.json:sediment` | 引擎出候选，人审写 | ≥5 条、ΣS≥3、跨度≥14 天；置信度**必须能降** |
| 意识层 | `conscious/state.json` | 气质只读 / 深层模式只写 | 反复发生的事改系数，不存成条目 |

**权限是设计的核心**：`consolidation.deposit()` 只把候选写到 `index/`，
`Store.write_self()` 只在人审后由 `MemorySystem.approve_candidates()` 调用。
引擎自己写 `self/` 就等于自己编记忆。

## 3. 变量定义（事件层）

| 变量 | 含义 | 写入时 | 随时间 |
| --- | --- | --- | --- |
| S | 意义强度：这件事有多重 | 标注 / 启发式 | 极慢，`e^(-λS·t)`，五年约 -7% |
| D0 / D | 初始细节完整度 / 当前值 | 标注 | **最快**，幂律衰减主战场 |
| E | 情绪残留 | 标注 | 慢，五年约掉一半 |
| C | 巩固程度：被回忆过几次 | 派生 `min(0.9, 0.1+0.18×recalls)` | 只涨不跌 |
| N | 干扰：相似记忆互相串味 | 每次 build 重算 | 二元组 Jaccard 近似 |
| R | 可检索性 | 现算 | 由上五项 + 线索命中加权 |
| Q | 重建可信度 | 现算 | `D / (1 + 推断比例)` |
| P | 当时的判断/立场（10~20 字） | 只能靠模型写 | **不参与 D 衰减**，按 S 曲线判活 |
| V / W / R(rel) / I | 情绪正负 / 和谁有关 / 关系权重 / 身份相关性 | 标注，可省略 | 喂人物模型与自我模型；省略比编造好 |

`S` 与 `D` 分开是整个设计的起点：细节掉光了，「这个人对我很重要」还在。
`P` 再进一步：肉掉了，骨头还在。

## 4. 公式（全部参数见 config.example.json）

```
τ    = τ0 · exp(k_s·S0 + k_e·E0 + k_c·C) / (1 + k_n·N)     忘得多慢
D(t) = D0 · (1 + t/τ)^(-p)                                  细节，幂律
λ(t) = p / (τ + t)                                          瞬时遗忘速率，越往后越慢
S(t) = S0 · e^(-λS·t)      E(t) = E0 · e^(-λE·t)
R    = .30·S + .22·E + .10·C + .10·e^(-t/30) − .15·N （检索时 +.28·cue）
Q    = D / (1 + inference)
半衰期 = τ · (2^(1/p) − 1)；p=1 时半衰期 == τ
```

**为什么幂律不是指数**：要求「D0=0.90、五年后 0.18」且「初期快、后期慢」，
纯指数做不到——半衰期短到能解释前几周，五年后必然归零。幂律才有长尾。
`tau` 必须用**当初**的 S0/E0/C 算，不用当下的 S/E，否则情绪一淡 τ 跟着缩，
衰减二次加速，五年后掉过头。

**生命周期**：`rule`（不衰减）/ `intact` (D≥.72) / `episodic` (≥.42) /
`fragment` (≥.15) / `residue` (S≥.45 或 E≥.30) / `faded`。
每档绑定一句**确定度口径**：细节还在可以说具体，只剩碎片不许补情节，faded 不主动提。
规矩单独拎出来，因为「说话三禁」不靠细节活着，硬当事件衰减一年后会被算成「已经忘了」。

## 5. 全链路：筛选 → 存储 → 检索 → 巩固 → 淘汰 → 回收

### 5.1 筛选（写入前）

- 蒸馏窗口默认 3 小时，游标回退 90 秒，最长 26 小时；不足 4 条不蒸馏且不推游标。
- 一次最多 120 条原文 / 6000 字符、最多产出 3 条；纯寒暄、纯表情不写。
- 每条必须带 `quote`（原文逐字 8~30 字），校验门槛 ≥6 字且**必须是原文子串**——防模型编原话。
- 正文 <8 字丢、>160 字截；同批按指纹去重；`W:无/未知` 之类脏值剔除，不让它进人物模型。
- 写前再对当日 `live/` 做一次指纹去重；游标只在三种成功/空结果情况下推进。
- 白天写 `live/`，23:45 日记任务写 `daily/`，23:55 把 live 并进 daily 再删 live。
- **live/ 条目默认按事件算**，只有明确落在「记住的」段才允许当规矩——
  否则一句随口的「以后」会永久挂在不衰减的常驻段里。

### 5.2 存储

- 原始证据只读、永不删；索引是派生的，删了能重建（会丢 `recalls` 计数）。
- 一切落盘走 `*.tmp-<pid>` → `os.replace` 原子写；覆盖前备份到 `backups/`。
- 事实层单一事实源 `facts.json` → 两版投影 `facts-private.md` / `facts-group.md`，
  铁律**值不过界**：`quiet` 群里只留「知道」，`secret` 群里整条不出现。
- 融合件 `merged-group.md`：群会话吃私聊+群聊+事实层合成的一份，群版只做两件机械转换
  （换称呼 + 硬挡 PII），其余由出口判断；`self/` 永远不进群（fail-closed）。
- 注入顺序：**我是谁 → 接着上次 → 感觉 → 看法 → 好奇 → 确认过的事实 → 事件 → 想起 → 触景**。
  先给主体再给记忆；反过来就是「我有一堆记忆，其中一些关于我」。

### 5.3 检索

- 每轮只读派生索引，不重扫日记：生产实测重扫 0.7s → 只读索引 ~0.17s（含 Python 启动），
  插件侧一轮约 0.37s，按消息文本缓存、一轮只跑一次。
- 手写〔线索〕命中给 0.9；否则退化成二元组重叠，重叠率 ≥0.25 才给分（上限 0.7）。
- `R_final = R + w_cue×match`，按 `(R, cue)` 排序取 top-k（默认 3），低于 `min_cue=0.5` 不硬凑。
- 「想起」段预算 700 字符、单行 110 字符，标题写明「不是刚发生的」，每行括号标确定度。

### 5.4 巩固 / 重固化

- `C = min(0.90, 0.10 + 0.18×recalls)`，只涨不跌。
- `touch()`：`recalls+1`，`D0 = min(0.98, D0×1.04)`，`last_recall` 更新；
  **原始日记一个字节都不动**。
- 每次回忆都在重构，反复提同一件事会让它更像自己编的版本——所以规则里明确
  「别反复拿同一件事当谈资」。

### 5.5 淘汰

- **不物理删除旧记忆。** faded 条目留在索引里（可审计、可被重新召回），只是不渲染。
- 规矩常驻 60 天后交给长期层，不在注入件重复。
- 真正被「淘汰」的是**进 prompt 的资格**：按阶段分段限额（rule 14 / intact 12 /
  episodic 12 / fragment 12 / residue 8），段内按 R 或时间排序截断。

### 5.6 内存 / 磁盘回收

- 注入预算 6000 字符（融合件 8000）；**分段裁剪**而不是最后硬截：
  按优先级先砍 `cues` → `recall` → `conscious` → 低档事件，保住生长层与沉淀段。
  最后才硬截并标注「后面截掉了」。
- 备份轮转 10 份；好感度 history 每人 30 条；自我模型 seen 超 500 删最旧 100；
  日志超 200000 字节停写/截断；临时情绪强度 <0.2 归零；会话结束清检索缓存。
- 上下文压缩是**模型侧**的另一件事：本仓库不实现压缩器，但给出预算与对接位
  （`budget.*_order` 对应 prompt-inject 的段顺序）。生产里用 20 万 token 阈值触发、
  保留比例 0.05；旧版定时压缩因会话已从 store 释放导致 checkpoint 失败，已弃用。

## 6. 与好感度 / 情绪的对接

见 `docs/INTEGRATION.md`。要点：三者时间尺度不同（幂律年级 / 天级 / 分钟级），
不互相写回；`V/W/R/I/E` 是记忆层流出的标注，`tier` 是情绪基线的输入。

## 7. 取舍与局限（明确写下来，别让用户自己踩）

| 取舍 | 换来了 | 代价 |
| --- | --- | --- |
| 零依赖、纯文本 + JSON | 可复现、可直接抽走、易审计 | 无事务、无并发锁、无语义检索 |
| 启发式兜底标注 | 不写标注也能跑 | 判不出「这件事有多重要」，S 集中在 0.35~0.62 |
| 二元组 Jaccard 当 N / 相似度 | 可解释、无需模型 | 同义不同词算不出干扰，也连不上边 |
| 幂律 + 六变量 | 有长尾、能区分轻重 | 参数多、彼此耦合，必须靠 `calibrate` 守形状 |
| 层多、权限细 | 深层不会被每轮对话改写 | 11 段注入件，模型可能只读前几段；每段必须硬预算 |
| 引擎只读 self/ | 不会自己编记忆 | 生长依赖人审/日记任务，冷启动时那几段是空的 |
| 原始证据永不删 | 可回溯、可重建 | 磁盘单调增长，需要外部归档策略 |
| 群聊 fail-closed 不读 self/ | 私事不进群 | 群里的「我」更薄，只剩事件与事实 |

**已知不一致（保留并标注，不悄悄抹平）**：
- 事件层 `lambda_e=0.00033`，意识层独立实现 `conscious.lambda_e=0.00038`；
  两者是不同模块的独立曲线，配置里分开列。
- 生产实现头部注释曾写「`--touch` 不改 D0」，实际代码会 `D0×1.04`（上限 0.98）；
  本仓库以**代码行为**为准，并在 `consolidation.touch()` 注释里明说重固化会轻微改变记忆。
- 旧版按天数硬切的分层与新版按分量衰减并存：本仓库把前者保留为读取视图，
  不宣称它已被删除。
