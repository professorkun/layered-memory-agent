## 一、一条更聪明的曲线，救不了记忆

最开始我给聊天机器人做的记忆，是最朴素的那种：近三天留原文，四到三十天压成每周要点，
三十一天以上压成一句话，最多留二十条。

跑久了发现，这套东西根本不叫遗忘，叫**定期删档**。随口一句「今天中午吃面」和一句
「你别送了」，在日历上是同一天，到了第三十一天一起被压扁。系统里没有「这件事有多重」
这个概念，只有「这件事多久了」。

上一篇文章解决了这一半：把细节完整度 D 单独拆出来，用幂律曲线让它按分量衰减，
意义强度 S 掉得极慢，情绪残留 E 掉得慢，被回忆过的 C 只涨不跌，相似的旧事用 N 互相串味。
五年后「很重的事」细节还剩 0.18，「随口一句」剩 0.04——曲线是对的。

但曲线对了，记忆还是不对。因为还有几个问题它一个都回答不了：

- 「说话别带括号旁白」这种**规矩**，凭什么跟事件一起按天数淡掉？
- 我**查到**一条资料，说出口时能不能说「我记得」？
- 一件旧事的细节掉光了、只剩下「当时觉得他其实在硬撑」，这个**判断**该存在哪儿？
- 反复发生的一类事，是再存一条记忆，还是**改掉我看待下一件事的方式**？
- 群里那几个人，凭什么能看到我私聊里长出来的感觉？

这些都不是「忘得多快」，是**分层**。所以这次把整套东西摊开讲：浅层与深层怎么划，
数据怎么在层间流动，哪一层允许谁写，以及这么拆要付出什么代价。

## 二、先分清三件被搅在一起的东西

第一刀不切时间，切**职责**。

| | 是什么 | 会消失吗 | 能不能说「我记得」 |
| --- | --- | --- | --- |
| 上下文 | 本轮这几句 | 说完就过去 | 只能说「你刚才说」 |
| 我的记忆 | 我怎么经历、怎么感觉、怎么想 | 按各自的曲线淡 | 可以，但要按确定度说 |
| 知识库 | 我们确认过的事实：课表、约定、称呼、查过的结论 | 改了才变 | **不可以** |

「库里写着 ≠ 我记得」这条看着像抬杠，实际天天用得上：查到教室号，只能说「库里写着」，
不能说「我记得是那间」——除非记忆里真有那一段。反过来，情绪、猜测、我当时怎么想、
我们之间私下的分寸，永远不进知识库。两边各走各的路，不互相搬运。

冲突时也有口径：**刚发生的事以上下文为准，事实类以记忆/知识库为准**，因为上下文里
可能只是有人在重复旧说法。两边对不上就说清楚：「我记得是旧值，你们说的那个是改之前的吧。」

## 三、浅层与深层：其实有两套分层，别接反了

### 3.1 按保鲜度分：给多少原文

最早那套按天数硬切，不该扔，该降级成「**读取视图**」：

- **L1**：最近 3 个自然日，原文全给，注入预算内尽量不截；
- **L2**：4~30 天，按周压成要点，每周最多 5 条、每条截到 60 字；
- **L3**：31 天以上，每天一句话，最多 20 条。

预算 4000 字时按「单条截断 → 每轮留最新几行 → 只留最近 12 轮」逐级压缩。
这一层只管**这一轮给多少原文**，不管**细节还剩多少**——后者是衰减引擎的事。两者正交。

### 3.2 按抽象程度分：从事件长成人

真正决定「这个机器人像不像同一个人」的是另一套分层：

| 层 | 是什么 | 谁写 | 衰减 |
| --- | --- | --- | --- |
| L0 底感 | 说不出从哪件事来，但一遇到就反应 | 手写，要人点头 | **不衰减**，5~9 条，半年复核 |
| L1 感觉 | 从旧事里沉下来的，记忆掉了它还在 | 引擎出候选，人审后写 | 极慢 |
| L2 事件 | 发生过什么 + 我当时怎么想 + 什么感觉 | 蒸馏器 / 日记任务 | 六变量幂律（上一篇那条曲线） |
| L3 沉淀 | 多条同类事件攒出的判断 | 引擎出候选，人审后写 | 置信度**可升可降** |
| 意识层 | 先天气质（只读）/ 深层模式（只写）/ 身体状态 | 事件累积 | 改系数，不存条目 |

最底下还有一层容易被忽略：**深层模式**。反复发生的事不存成第 N 条记忆，
而是把「信任更新偏向」「失联敏感度」这类系数推一点点；系数反过来改下一次的评价。
这就是「记忆模糊了，但结构还在」。只靠「人设 + 检索 + 规则」，同一句「你怎么又没回」，
第一天和第一年的反应会一模一样——那不是记性，是拼装。

### 3.3 两套编号撞名，是接线时最容易错的地方

注意：3.1 的 L1/L2/L3 是**时间远近**，3.2 的 L0~L3 是**抽象程度**。
两处的「L2」指的根本不是同一个东西。生产代码早期就吃过这个亏，所以开源实现里
一律用语义名（`Layer.EPISODIC`、`Layer.GROWTH_BASE` …），只有旧读取视图保留数字编号，
并在返回值里写明「编号不通用」。

## 四、层间怎么流动：写入权限才是设计核心

分层不是多建几个文件夹，是给每层规定**谁能写**。

```
原始对话（只读，永不删）
   │  蒸馏筛选
   ▼
live/   浅层·当天增量 ──23:55 合并──▶ daily/  事件层·按日归档
                                          │ 重算
                                          ▼
                                  index/forget-index.json（派生，删了能重建）
                                          │ 分段渲染
                                          ▼
                       out/private.md / group.md / merged-group.md  ──▶ 注入 prompt
```

几条硬规则：

1. **原始证据只读**。改写记忆不动 `daily/`，删索引能重建（会丢 `recalls` 计数）。
   一切落盘走 `*.tmp → os.replace` 原子写，覆盖前留备份。
2. **引擎只读生长层**。`deposit()` 只把「感觉候选 / 沉淀候选 / 联结边」写到 `index/`，
   绝不直接改 `self/`。要落盘必须人审后显式调用 `approve_candidates()`。
   引擎自己写 `self/` 就等于自己编记忆——这条边界比算法重要。
3. **事实层单一事实源 + 两版投影**。`facts.json` 里每条带
   `vis: public | quiet | secret`；渲染群版时铁律是**值不过界**：
   quiet 只留「知道，不在这儿报」，secret 整条不出现。手机、住址、学号、身份证、
   账目数字一律硬挡，不参与判断。这样即便哪天群记忆被误引，也没有数字可漏。
4. **群聊 fail-closed**。群会话吃一份融合件（私聊 + 群聊 + 事实层合成），
   群版只做两件机械转换：换称呼、挡 PII，其余原文照给、出口自己判；
   但 `self/`（状态、感觉、沉淀）**永远不进群**——不是隐私，是分寸。
5. **注入顺序：先给主体，再给记忆**。
   `我是谁 → 接着上次 → 现在的感觉 → 沉淀下来的看法 → 还没弄明白的 →
   确认过的事实 → 一直记着的 → 最近/轮廓/碎片/只剩情绪 → 想起 → 触景`。
   反过来就成了「我有一堆记忆，其中一些关于我」——那是数据库，不是人。
6. **连续性不许假装**。状态快照超过 36 小时，标题降成「接着上次（N 天前）」；
   超过 7 天干脆不出现。宁可说上次是哪天，也不能写「接着昨天」。

层间的三条生长规则也都有阈值，不靠模型自由发挥：
`residue` 且 E≥0.30、连续 7 天 → 感觉候选；同主题 ≥5 条、ΣS≥3.0、跨度 ≥14 天 →
沉淀候选；出现分量重但结论相反的事，置信 −0.15，跌破 0.40 就渲染成「（我可能想错了）」。
只增不减的沉淀，会把人变成固执的人设。

## 五、事件层内部：变量与公式（只占一层）

上一篇文章论证过为什么用幂律，这里只把它当作**一层的内部机制**列出，参数一个不藏。

| 变量 | 含义 | 怎么写进去 |
| --- | --- | --- |
| S | 意义强度：这件事有多重 | 标注 / 启发式，掉得极慢（五年约 −7%） |
| D0 / D | 初始 / 当前细节完整度 | 标注，遗忘主战场 |
| E | 情绪残留 | 标注，五年约掉一半 |
| C | 巩固程度 | **派生**：`min(0.90, 0.10 + 0.18 × recalls)`，只涨不跌 |
| N | 干扰：相似记忆串味 | 每次 build 用二元组 Jaccard 重算 |
| R | 可检索性 | 现算，检索时再加线索命中 |
| Q | 重建可信度 | `D / (1 + 推断比例)` |
| P | 当时的判断（10~20 字） | 只能靠模型写；**不参与 D 衰减**，肉掉了骨头还在 |

条目前面还可选 `V`（情绪正负 −1~1）、`W`（和谁有关）、`R`（关系权重）、
`I`（身份相关性），它们喂的是人物模型和自我模型。**省略比编造好**：
缺省值表示「不知道」，编错一个 W 会一直错下去。

```
τ      = τ0 · exp(k_s·S0 + k_e·E0 + k_c·C) / (1 + k_n·N)      忘得多慢
D(t)   = D0 · (1 + t/τ)^(-p)                                    细节，幂律
λ(t)   = p / (τ + t)                                            瞬时速率，越往后越慢
S(t)   = S0 · e^(-λS·t)        E(t) = E0 · e^(-λE·t)
R      = .30·S + .22·E + .10·C + .10·e^(-t/30) − .15·N  （检索时 +.28·cue）
Q      = D / (1 + inference)
半衰期 = τ · (2^(1/p) − 1)，p=1 时半衰期 == τ
```

默认参数：`tau0=41, k_s=1.5, k_e=1.0, k_c=0.5, k_n=1.5, p=1.0,
lambda_s=0.00004, lambda_e=0.00033, recency_tau=30`。
τ 必须用**当初**的 S0/E0/C 算，不能用当下的 S/E，否则情绪一淡 τ 跟着缩，
衰减二次加速，五年后会掉过头。

校准用两个案例反解（`calibrate` 命令可复现）：

| | 1 年后 D | 5 年后 D | 5 年后 S | 5 年后 E | τ |
| --- | --- | --- | --- | --- | --- |
| 很重的事 S0=.95 E0=.90 D0=.90 | 0.49 | **0.18** | 0.88 | 0.49 | 441 天 |
| 随口一句 S0=.35 E0=.15 D0=.85 | 0.16 | **0.04** | 0.33 | 0.08 | 85 天 |

**生命周期**按 D 分档：`rule`（规矩，不衰减）/ `intact`(≥0.72) / `episodic`(≥0.42) /
`fragment`(≥0.15) / `residue`(S≥0.45 或 E≥0.30) / `faded`。
每一档绑一句**确定度口径**：细节还在可以说几点、在哪、说了什么；记得轮廓只能说大概；
只剩碎片别补情节别排顺序；只剩意义和情绪就不复述发生了什么；没记着就说记不清了。
任何时候都不说「我百分之百记得那天就是这样」。

规矩单独拎出来，是因为它不靠细节活着。硬把它当事件衰减，一年后「说话三禁」
会被算成「已经忘了」——那是模型错，不是数据错。但带具体日期的「记住的」条目
（比如某场考试）要降级成事件：过了就过了，该跟着时间淡。

## 六、全链路：筛选、存储、检索、巩固、淘汰、回收

### 筛选

蒸馏窗口默认 3 小时、游标回退 90 秒、最长 26 小时；不足 4 条不蒸馏且不推游标；
一次最多 120 条原文 / 6000 字符、最多产出 3 条。纯寒暄、纯表情不写。
每条必须带 `quote`——从原文逐字复制的 8~30 字，校验时要求是原文子串，
**防的是模型编原话**。正文 <8 字丢、>160 字截；同批按指纹去重。
`live/` 条目默认一律按事件算，只有明确落在「记住的」段才允许当规矩，
否则一句随口的「以后」会永久挂在不衰减的常驻段里。

### 存储

事实层之外都是「原始证据 + 派生索引 + 注入件」三件套。索引里存 S/D0/E/C/N/cues/
recalls/标注，正文原文只在日记里。`raw/`、`daily/` 永不删；
`forget-index.json`、`link-index.json`、边权、候选全是派生的。

### 检索

每轮只读派生索引，**不重扫日记**：生产实测全量重扫约 0.7 秒，
改走只读索引后约 170 ms（含 Python 启动），插件侧一轮约 0.37 秒，按消息文本缓存、
一轮只跑一次。手写〔线索〕命中给 0.9；否则退化成字符二元组重叠，重叠率 ≥0.25 才给分
（上限 0.7）。最终按 `R + 0.28×命中度` 排序取 top-3，低于阈值 `0.5` 就返回空——
**不硬凑**，问得含糊本来就该回「没印象」。
「想起」段预算 700 字符，标题写明「不是刚发生的」，每行括号标确定度。

### 巩固

回忆不是免费的。`touch()` 记一次：`recalls+1`、C 上升、
`D0 = min(0.98, D0 × 1.04)`（重固化会**轻微改变**记忆），`last_recall` 更新，
但**原始日记一个字节都不动**。每次回忆都在重构，反复拿同一件事当谈资，
它就更像自己编的版本一点。（顺带说明：生产实现的头部注释曾写「D0 不变」，
代码实际会改，开源版以代码行为为准并写进注释。）

### 淘汰

**不物理删除旧记忆**。faded 条目留在索引里，可审计、可被重新召回，只是不渲染。
规矩常驻 60 天后交给长期层。真正被淘汰的是**进 prompt 的资格**：
各阶段分段限额（rule 14 / intact 12 / episodic 12 / fragment 12 / residue 8），
段内按 R 或时间排序截断。

### 内存与磁盘回收

注入件预算 6000 字符（融合件 8000 / 想起段 700 / 意识层 1400）。
关键是**分段裁剪而不是最后硬截**：给每段定优先级，超预算从最低的开始砍——
触景 → 想起 → 意识层 → 低档事件，保住「我是谁 / 沉淀下来的看法」。
硬截会把沉淀段从中间切一半，那是最坏的结果。只有全部砍完仍超，才硬截并标注。

其余回收项：备份轮转 10 份、好感度 history 每人 30 条、自我模型 seen 超 500 删最旧 100、
日志超 200 KB 停写、临时情绪强度 <0.2 归零、会话结束清检索缓存、`live/` 合并后删除。
模型侧的上下文压缩另算：阈值驱动（20 万 token / 保留比例 0.05），
旧版定时压缩因为会话已从 store 释放导致 checkpoint 失败，已弃用。

### 性能瓶颈（不藏）

干扰度 N 是**全库两两比字符二元组，O(M²·L)**，这是头号瓶颈。
生产 50 条时 129 条边、无感；M>1000 就该换成按 cue 倒排只算有共享线索的对，
或者干脆换向量索引。检索是 O(M·L)，渲染 O(M log M)，GC O(文件数)。
`pressure` 命令直接输出需要比较多少对（`M(M−1)/2`）和各项预算，方便判断何时该升级。
完整的实测数字与升级路线在仓库 `docs/PERFORMANCE.md`。

## 七、和好感度、情绪模块的对接规范

三个模块**时间尺度不同**，这是全部规则的第一条：

| 模块 | 变化速度 | 存储 | 谁能改 |
| --- | --- | --- | --- |
| 事件记忆 | 幂律，年级长尾 | 日记 + 索引 | 蒸馏器/日记任务；引擎只算派生量 |
| 好感度内账 | 天级（7 天无互动后每天 −1） | `affinity.json` | 回合规则记分，**模型不许自己改** |
| 情绪状态 | 分钟级（半衰 3~60 分钟） | `emotion.json` | 事件触发 + 真实时间衰减 |

不互相写回：好感度不写进记忆条目，情绪不写进日记，记忆也不直接改档位。

**记忆层流出的标注**是 `V / W / R(rel) / I / E / S / P`：
W 决定「当事人此刻是否在场」（不在场激活分 ×0.55），
V 与当前 mood 算共鸣 `cong = 1 − |mood − V|/2`，
rel 进在场权重 `P = 0.35 + 0.45·在场 + 0.20·rel`，
E 进情绪维，S/D 进时间维 `T = 0.55·S + 0.45·D`，
最后 `A = (M^.45 · P^.16 · Emo^.16 · T^.23) × attention`，
过阈值 `theta=0.34` 才进意识，同组弱者侧抑制 ×0.78，一轮最多 4 条。
（注意别把标注里的 `R` 关系权重和公式里的 `R` 可检索性接反。）

**好感度 → 情绪基线**：档位下界 90/75/55/25/0 对应自家人/死党/朋友/熟人/对头；
基线情绪依次 happy/happy/friendly/calm/cold。群氛围 <35 整体降一档，
>70 只升到 friendly 不跨到开心；降档迟滞 3 分防门槛抖动。
情绪半衰（分钟）：angry 10、annoyed **3**、hurt 10、happy 10、sleepy 30、
cold/calm/friendly 60；强度低于 0.2 归零；同强度负面优先；
`switch_guard=0.4` + 30 分钟窗口保证一段对话最多换一次情绪。

记分防刷链固定：单次 ±2（辱骂类 ±3）→ ≥80 正增益 ×0.3 / ≥95 ×0.1 →
每日净变化 ≤8 → 每日 ≤6 次事件 → 同人 10 分钟冷却 → 落盘（history 留 30 条）。

**注入话术**（这条比数值更要紧）：群里永远不报好感度数字、不说这套账存在、
不把「情绪=happy(60%)」这一行念出来；事实三档口径是「直说 / 知道，不在这儿报 /
这个不在群里聊」；「登记 / 报一下 / 资料库 / 权限 / 我没有这个信息」这类词一出口，
就是把记忆系统端到人前，比漏一条信息更伤。

## 八、取舍：换来了什么，付出了什么

| 取舍 | 换来了 | 代价 |
| --- | --- | --- |
| 纯文本 + JSON，零依赖 | 可复现、能整目录搬走、逐行可审计 | 无事务、无跨进程锁、无语义检索 |
| 启发式兜底标注 | 不写标注也能跑 | 判不出「这件事有多重要」，S 挤在 0.35~0.62 |
| 二元组 Jaccard 当相似度 | 可解释、不依赖模型 | 同义不同词算不出干扰，也连不上边 |
| 幂律 + 六变量 | 有长尾、能区分轻重 | 参数互相耦合，必须靠 `calibrate` 守形状 |
| 层多、权限细 | 深层不会被每轮对话改写 | 11 段注入件，模型可能只读前几段，每段必须硬预算 |
| 引擎只读 `self/` | 不会自己编记忆 | 生长依赖人审，冷启动时那几段是空的 |
| 原始证据永不删 | 可回溯、可重建 | 磁盘单调增长，要外部归档策略 |
| 群聊不读 `self/` | 私事不进群 | 群里的「我」更薄，只剩事件与事实 |

## 九、局限（写清楚，别让人自己踩）

1. 启发式判不出「这件事对他到底多重要」，接 LLM 标注器比调参有效得多。
2. 二元组不是语义：换 vector 检索要替换 `noise_level` / `cue_match` 两个函数，
   分层与衰减不用动——这是刻意留的接口。
3. 层多稀释注意力；沉淀最容易长歪且自己看不出来，置信度必须能降、周任务必须审；
   好奇最容易编，宁可这一栏空着。
4. 生长层冷启动是空的。底感得从真实对话里长，不该替它编。
5. 纯文件存储：多进程同时写会丢条目，生产请单写者或加文件锁。
6. 事件层 `lambda_e=0.00033`、意识层独立实现 `0.00038`，两处数值不同是历史事实，
   开源版保留并分别列在配置里，不悄悄抹平。
7. 旧版按天数硬切与新版按分量衰减并存：前者降级成读取视图，不宣称它已被删掉。

## 结语

上一篇解决的是「一条记忆怎么淡」，这一篇解决的是「哪些东西压根不该淡、
淡完之后该变成什么」。前者是曲线，后者是结构。

只有曲线的系统，最后出来的是一本会褪色的账本；
有了分层、权限和「先给主体再给记忆」的顺序，才慢慢有那个「他」。

但别把这套东西当成通用记忆架构：它是一台单人聊天机器人在真实对话里长出来的，
很多阈值是为了它的语气和它的隐私边界定的。真正值得抄走的不是那几个数字，
而是三条：**原始证据不可变、派生件可重建、越深的层越不该被每轮对话改写**。
