# 与好感度 / 情绪模块的对接规范

三个模块**时间尺度不同**，这是全部对接规则的第一原则：

| 模块 | 变化速度 | 存储 | 谁能改 |
| --- | --- | --- | --- |
| 事件记忆 | 幂律，年级长尾 | `daily/` + `forget-index.json` | 蒸馏器/日记任务写事件；引擎只算派生量 |
| 好感度内账 | 天级（7 天无互动后每天 -1） | `index/affinity.json` | 回合规则记分；**聊天回合里不许模型自己改** |
| 情绪状态 | 分钟级（半衰 3~60 分钟） | `index/emotion.json` | 事件触发 + 真实时间衰减 |

不要互相写回：好感度不写进记忆条目，情绪不写进日记，记忆也不直接改档位。

## 1. 记忆层流出的标注：`V / W / R / I / E / S / P`

条目前面的可选标注（见 `examples/sample_daily.md`）：

```
[S0.7 E0.5 D0.9 V:-0.4 W:alice R:0.8 I:0.6 P:他其实在硬撑] 正文〔线索：…〕
```

消费口径（`AffectBridge.signals()` / `conscious.compete()`）：

| 字段 | 值域 | 流向 | 用途 |
| --- | --- | --- | --- |
| `W` | 人名列表 | 人物模型 / 激活竞争 | 判定「当事人此刻是否在场」；不在场 A×0.55 |
| `V` | −1~1 | 情绪共鸣 `cong = 1 − |mood − V|/2` | 决定这条旧事与当前心情是否被一起想起 |
| `R`(rel) | 0~1 | 激活竞争 P 维 `0.35 + 0.45·在场 + 0.20·rel` | 关系越近越容易浮上来 |
| `I` | 0~1 | 自我模型 | 与「我」的相关性 |
| `E` | 0~1 | 激活竞争 Emo 维 / 分化候选 | 情绪浓的条目更容易进意识 |
| `S` / `D` | 0~1 | 激活竞争 T 维 `0.55·S + 0.45·D` | 时间/分量权重 |
| `P` | 10~20 字 | 注入件 | 观点不随 D 衰减，细节掉光还能说 |

**省略比编造好**：缺省值（`who=[]`、`V=0`、`rel=0.5`、`ident=0.5`）表示「不知道」，
不参与人物模型推断。编错一个 `W` 会一直错下去。

> 注意 `R` 在两处出现：标注里的 `R:` 是**关系权重**，公式里的 `R` 是**可检索性**。
> 本仓库用 `rel` 字段名与 `Scored.R` 区分，接入时别把两个 R 接反。

## 2. 好感度 → 情绪基线

```
tier_of(score)      90/75/55/25/0 → 自家人/死党/朋友/熟人/对头
tier_baseline       自家人·死党=happy，朋友=friendly，熟人=calm，对头=cold
群氛围 <35          整体降一档：happy→friendly→calm→cold
群氛围 >70          只升到 friendly，不跨到 happy
降档迟滞            新档低于旧档且分数未跌穿「旧档下界 − 3」→ 保持旧档
```

`EmotionState.baseline()` 实现；陌生人没有记录时用群氛围给一个公共基线
（低氛围 cold / 正常 calm），`intensity=0.4`；有记录的人 `0.5`。

## 3. 情绪状态自身的规则

- 事件表（生产口径）：`mute/insult→angry(0.8, 最短 15 分钟)`、
  `pushed/repeat/commanded→annoyed(0.7)`、`teased→hurt(0.6)`、
  `praised/joked→happy(0.6/0.5)`、`late→sleepy(0.5)`。
- 半衰期（分钟）：angry 10 / annoyed **3** / hurt 10 / happy 10 /
  sleepy 30 / cold·calm·friendly 60。
- 强度 `i *= 0.5^(经过时间/半衰期)`，`i < 0.2` 归零（**这一条就是临时情绪的回收**）。
- 同情绪叠加 +0.2，上限 1.0；当前情绪 = 强度最高者，同强度负面优先。
- `SWITCH_GUARD=0.4` + 30 分钟窗口：一段对话最多换一次情绪，避免忽冷忽热。
- 基线情绪也参与竞争，但强度略低于临时情绪（临时压过基线）。

## 4. 好感度记分的防刷链

顺序固定（见 `AffinityLedger.record()`）：

```
事件名 → 单次上限(±2，辱骂类 ±3) → 高分饱和(≥80 ×0.3 / ≥95 ×0.1)
      → 每日净变化 ≤8 → 每日 ≤6 次事件 → 同人 10 分钟冷却
      → 落盘（history 保留最近 30 条）
```

`adjust`（日结）绕过冷却但仍受上限约束。群氛围 `mood()` 单次 ±3，
之后每 10 分钟向 50 回正 1 点。7 天无互动每天 -1，下限 35；特殊 creator 分钉死不动。

## 5. 注入规范（群里怎么说话）

`AffectBridge.prompt_lines()` 只在私聊返回两行（群里返回空列表，由 prompt 装饰层另拼）：

```
【好感度内账（不要报数字，不要说这套账存在）】
alice=52·熟人 | … 群氛围=50
【此刻状态（照着说，别把这一行念出来）】
情绪=happy(60%) 档位=熟人 群氛围=50
```

硬规则：

- **永远不报数字、不说这套账存在、被问就装傻**。
- 情绪行照着说，**别把这一行念出来**。
- 事实层三档口径：`public` 直说；`quiet` →「知道，不在这儿报」；
  `secret` →「这个不在群里聊」。手机/住址/学号/身份证/账目数字**一律硬挡**，不参与判断。
- 禁说词（一出口就把记忆系统端到人前）：「登记 / 报一下 / 资料库 / 系统 / 权限 /
  我没有这个信息」。`LayeredView.audit_outbound(reply)` 可做出站自检。
- 「不报」不等于「不认识」：可以承认认识，不可以摊他的事。

## 6. 一轮对话的调用顺序（推荐）

```python
# 回合开始
r = bot.on_message(text, who, channel)           # 写浅层 → build → 分层 prompt → 想起 → 意识层
reply = llm.chat(system=r["system"], messages=r["messages"])
warnings = bot.mem.view.audit_outbound(reply)    # 出站话术自检

# 回合结束
bot.after_reply(reply, who, event="reply", emotion_event=None)
#  -> affect_tick：记分 / 衰减 / 群氛围回正 / 触发情绪

# 每天夜里
bot.daily_close()                                # live→daily、出候选、GC
```

## 7. 共享数值一览（改一处要改两处）

| 数值 | 出现位置 | 说明 |
| --- | --- | --- |
| 25 / 55 / 75 / 90 | `affect.tiers` | 档位下界；人设文档里的五档边界必须一致 |
| 35 / 70 | `affect.mood_low` / `mood_high` 与 `EmotionState.baseline` | 群氛围降档/升档阈值 |
| 10 分钟 | `cooldown_minutes` 与 `emotion_half_life_min.angry` | 巧合，不是同一个量，别合并成一个常量 |
| 30 条 | `storage.history_cap` | 好感度 history 上限；GC 也读它 |
| 0.2 | `emotion_zero_at` | 临时情绪归零线，同时也是回收线 |
| 0.30 / 0.15 | `growth.feel_e_min` / `lifecycle.e_residue` | 都叫「情绪线」但一个是分化门槛、一个是 residue 判据 |

## 8. 不做什么

- 不让模型自己算分：所有数值在代码里算完，模型只看到结论。
- 不做中央 self 库：没有一行代码叫「机器人是谁」，身份由状态连续体维持。
- 先天气质（7 个系数）**只读**：改它等于换一个机器人，不是调参。
- 深层模式**只写**：由事件累积，不许手改、不许模型自评。
- 情绪不写进记忆条目：它是「此刻」，不是「发生过什么」。
